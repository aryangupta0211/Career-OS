# CareerOS Vault — Complete implementation plan



Product specification

9 implementation phases



## Overall objective

Build a secure, cloud-based career document management system that allows users to:

- Store resumes and maintain their version history.
- Save job descriptions, even after job postings expire.
- Upload documents, screenshots, images and other career-related files.
- Link every document to relevant companies and applications.
- Access documents from any device.
- Find everything needed for an interview quickly.
- Monitor and manage storage usage.

Core principle: One document, one canonical record, multiple connected locations throughout CareerOS.

# Phase 1 — Secure storage infrastructure and database foundation

Critical

Build the foundation before creating the Vault UI.

### 1. Supabase Storage integration

Use private Supabase Storage buckets to store actual files.

The database should store file metadata and relationships, not file contents.

Implement:

- Private file storage.
- User-specific file paths.
- Secure upload and download.
- Signed URLs for temporary access.
- File ownership validation.
- File type validation.
- File size validation.
- Upload failure handling.
- Storage cleanup and reconciliation.

### 2. Database architecture

Proposed logical entities:

| Entity              | Responsibility                         |
| ------------------- | -------------------------------------- |
| VaultFile           | Canonical file metadata                |
| ResumeGroup         | Groups resumes by role or purpose      |
| ResumeVersion       | Maintains immutable resume versions    |
| JobDescription      | Stores job description information     |
| CompanyResource     | Stores company-related links/resources |
| ApplicationDocument | Connects files to applications         |
| CompanyDocument     | Connects files to companies            |
| DocumentTag         | Categorizes documents                  |
| StorageUsage        | Tracks storage consumption             |

These are logical responsibilities. Antigravity must inspect the current schema before deciding which require separate Prisma models.

### 3. Storage quota architecture

Implement configurable settings for:

- Total storage budget.
- Per-user storage quota.
- Maximum file size.
- Allowed file types.
- Storage warning threshold.

Important: Do not promise 1 GB per user automatically.

First calculate the actual available Supabase project storage and expected usage. Keep quotas configurable so we can change them without redesigning the system.

### Expected outcome

A secure, tested backend foundation ready to accept file uploads.

# Phase 6 — Productivity and intelligent features

Advanced features

Now we add the five features we discussed.

### 1. Resume-to-application matching

When creating an application:

- Identify the job role.
- Read resume role tags and skills.
- Suggest relevant resume versions.
- Show the reason for each suggestion.
- Let the user choose manually.

AI-based semantic matching can be introduced later.

### 2. JD skill extraction

Extract:

- Technical skills.
- Programming languages.
- Frameworks.
- Tools.
- Experience requirements.
- Education requirements.
- Responsibilities.

Allow users to review and correct extracted information.

### 3. Preparation checklist generation

Use extracted JD requirements to suggest preparation tasks.

Example:

Deloitte SDE requirements:

- Java.
- DSA.
- SQL.
- GenAI.

Suggested tasks:

- Revise Java Collections.
- Practice DSA questions.
- Revise SQL joins.
- Study GenAI fundamentals.

Connect generated tasks to the existing Tasks module.

### 4. Duplicate detection

Use SHA-256 hashing.

When the same file is uploaded again:

- Detect identical content.
- Notify the user.
- Offer to reuse the existing file.
- Allow the user to cancel.

Never automatically delete files.

### 5. Document search

Build two levels:

Metadata search: Filename, description, company, role and tags.

Content search: Extracted text from supported PDF, DOCX and TXT files.

Content search should come after basic metadata search and must respect user-level authorization.

### Expected outcome

The Vault becomes a useful career research and preparation workspace, not merely cloud storage.

## 11. Rules for the entire implementation

These are non-negotiable across all phases:

1. Preserve existing authentication.
2. Preserve existing applications, companies, contacts, tasks and calendar.
3. Reuse existing database models wherever practical.
4. Do not create duplicate document records for different pages.
5. Never overwrite historical resume versions.
6. Never make private files publicly accessible.
7. Never silently switch to demo data.
8. Never reset the database.
9. Review every new migration before applying it.
10. Do not introduce expensive AI dependencies for basic Vault operations.
11. Make every feature usable on desktop, tablet and mobile.
12. Keep the interface consistent with the Attio-inspired CareerOS design.

## 12. Our execution strategy

I recommend assigning Antigravity the entire Vault project, but with phase-based implementation and verification checkpoints.

The agent should not pause after every small UI component. It should complete related work together, test it, and continue.

However, it must stop for your approval at these points:

- Database migration review.
- Storage bucket and security configuration.
- Any production database changes.
- Any change that could delete or invalidate existing records.

Before writing the master prompt, there are two things I want us to preserve as design decisions:

- The Vault should be a first-class sidebar destination, not buried inside Settings.
- Every company and application page should have a clearly visible Documents/Resources section, even though the actual files live in one centralized Vault.

My recommendation is to use this plan as the implementation baseline. Next, we can turn it into a detailed Antigravity master prompt with exact database models, API contracts, UI layouts, validation rules, security requirements and testing instructions.
